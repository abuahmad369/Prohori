# Research: the next software era (November 2026)

This file holds the evidence behind the company scenario in [scenario.md](scenario.md). Most figures come from vendor reports, surveys or press coverage, not audited data. Each one is marked with its source so it can be rechecked before it goes into a pitch.

## The five findings that matter

1. **Writing code is no longer the bottleneck.** Professional developers report that 40 to 50 percent of their code is now written by AI agents. Direct measurement puts AI-written production code nearer 27 percent, which is still a large and growing share.
2. **Checking code is the new bottleneck.** In Veracode's 2026 tests, about 44 percent of AI code generation tasks introduced a risky security flaw. Developers say reviewing AI code takes more effort than reviewing a colleague's.
3. **AI-built apps fail in production for boring reasons.** The public breaches of 2026 came from missing database access rules, secrets left in code and no security review before launch, not from clever attacks.
4. **Buyers are starting to pay for outcomes, not tools.** Investors now describe the next large software companies as ones that sell finished work, priced per result.
5. **Regulation is turning trust into a requirement.** The EU Cyber Resilience Act requires vulnerability reporting from 11 September 2026 and a machine-readable software bill of materials (SBOM) from 11 December 2027.

The conclusion drawn from these: **when making software becomes nearly free, the scarce thing is trust.** That means knowing an app is safe, works as described and will keep working.

## 2. How safe AI-written code is

| Source | Finding |
|---|---|
| Veracode 2026 GenAI Code Security Report | About 44% of AI code generation tasks introduced a risky vulnerability. The average security pass rate across models was 56%, nearly unchanged from the year before. |
| Veracode Spring 2026 update | Pass rate against cross-site scripting (CWE-80) was 15%; against log injection (CWE-117), 13%. Java was the weakest language. |
| IOActive whitepaper (April/May 2026) | 31.6% of AI-generated code samples were fully exploitable under a stricter method. |

These come from different benchmarks and are not directly comparable. Together they show that roughly a quarter to a half of AI-written code carries a real security problem unless someone checks it.

## 3. What actually broke in 2026

- **Moltbook** (January 2026): a vibe-coded social network was breached within three days of launch. A Supabase database with no row-level security exposed 1.5 million API tokens and 35,000 email addresses.
- **Lovable**: press reports describe three documented incidents, including an access-control flaw that stayed open for 48 days. A researcher claims one Lovable-hosted app exposed about 18,000 user records (unverified, from a vendor blog).
- **Escape.tech scan of 5,600 public vibe-coded apps**: more than 2,000 high-impact vulnerabilities, 400+ exposed secrets and 175 cases of exposed personal data (vendor data).
- **Cloud Security Alliance research note (April 2026)**: more than 20 documented incidents, most linked to AI-assisted apps deployed without a security review.

The common causes across reports are the same three: missing database access rules (for example Supabase tables without row-level security), secrets in code or in browser-visible settings, and no review before launch. One write-up summarised it as: production safeguards were never added because the AI wasn't asked for them.

**Implication:** a checker tuned to these specific, repeated mistakes catches most real-world damage. This is what the Prohori audit engine targets first.

## 5. From tools to outcomes ("service as software")

- Sequoia's March 2026 essay "Services: The New Software" (Julien Bek) argues the next large companies sell the work itself, priced per outcome.
- Y Combinator's Spring 2026 Request for Startups is reported to include "AI-native agencies" (not confirmed against YC's own page).
- Intercom's Fin charges $0.99 per resolved support conversation, the standard example of outcome pricing.
- An Orb review of 80 AI-agent companies found only 3.8% use pure outcome pricing; most mix subscription and usage. The shift is real but early.

**Implication:** charging per fixed problem ("we fixed 12 critical issues, $5 each") fits buyers better than another dashboard subscription.

## 6. Regulation: the EU Cyber Resilience Act

- **11 September 2026:** vulnerability and incident reporting duties start (24-hour reporting of actively exploited vulnerabilities).
- **11 December 2027:** manufacturers, including software publishers selling into the EU, must produce a machine-readable SBOM covering at least top-level dependencies, keep it current and hand it to market-surveillance authorities on request. SBOMs don't have to be public.
- The Commission may later fix the SBOM format through implementing acts.

**Implication:** SBOM generation and vulnerability tracking become a compliance purchase, not a nice-to-have, for anyone selling software in Europe.

## 7. The scanner market is already crowded

- One tracker counted 8 scanners for vibe-coded apps in one week and 17 a little later.
- Example prices: Vibe App Scanner $5 to $29 per month; VibeSafe $39 pre-launch audit and $19 post-launch scan; other audit services at $99 (48 hours) and $299 (72 hours).
- Lovable added built-in security scanning in version 2.0.
- Incumbent code-security companies (Snyk, Semgrep, Sonar, GitHub Advanced Security) sell to professional engineering teams. Their pricing was not covered by this research.

**Implication:** a plain scanner is a commodity. It works as the free entry point, not as the business. The business has to be built on what a scanner alone can't offer: certification people trust, a marketplace that only lists checked apps, fixes priced per result, continuous monitoring and compliance.
